# UX Acceptance Gate

A redesign candidate is not promoted merely because files load.

## Required student-facing gates

- light-first reading experience;
- optional dark mode;
- readable body typography; monospace restricted to IDs/code;
- Study View separated from Audit View;
- question, worked explanation, exam answer and recall mode discoverable;
- semantic color is meaningful and not the only signal;
- SOURCE_LIMITED / SOURCE_CONFLICT remain unmistakable;
- every question has a meaningful figure or an explicit governed no-figure rationale;
- quantitative plots never invent data;
- iteration/comparison content can become tables when structured metadata exists;
- related-question links identify their heuristic/non-authoritative status;
- mobile 320 / 390 / 430, tablet and desktop widths;
- no page-wide horizontal overflow;
- keyboard focus visible;
- no hover-only essential information;
- print/grayscale remains intelligible;
- local retrieval state cannot mutate academic content.

## Release gates

Drive freeze/readback → new working branch → independent GitHub readback → representative student UX review → correction → candidate → tag/release → separate Pages promotion → deployed artifact + public browser verification.
